# DCD 200*01 Markdown Reflection
## By Isaac McDonald. 9/3/2026
Markdown is a markup language used to edit and create text documents. What makes Markdown stand out from others is the ability to use tools within Markdown to customize text to eventually convert it to HTML. I want to cover what John Gruber covers in Markdown and his questions he leaves readers to interpret. 
1. Markdown is incredibly simple to get into and understand documentation with. Paragraphs, headers, and other tools can be navigated with a simple [Cheatsheet](https://github.com/adam-p/markdown-here/wiki/markdown-cheatsheet "Markdown Cheatsheet") that's setup is clean and allows smooth navigation. No external software is needed to use markdown. Essays and online posts with the intention of written information can be done, but Markdown's structure doesn't allow more complex things like tables, footnotes, and metadata. Markdown isn't a neutral, as it pertains to specific types of writing and leaves other more complex to organize information outside.

2. Usage of regular expression over grammar demonstrates Markdown's priority of simplicity and practicality. Markdown has the capability (and intention) to convert text into HTML. This works out for simple text, though when specific syntax is needed to interact with one another Markdown struggles. As more people began using Markdown more complex usages began arising, eventually resulting in CommonMark. More rules formed around Markdown with how it gets parsed. Markdown's simple nature had caused several roadblocks when users attempted to make more complex creations as the language grew.

Markdown is a text editor that maximizes its simplicity for public use. Though this had caused roadblocks along the way with more complex scenarios not being able to be done on Markdown. Although John Gruber argues that Markdown will become the new normal, that is only for more simple editors. WYSIWYG will still remain, albeit in more specific scenarios.
